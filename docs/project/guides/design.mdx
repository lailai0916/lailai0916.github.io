## 定位

本指南适用于我的数字界面、平面设计、排版、图像和数据展示。网站是当前最完整的应用实例，但这里的原则不依赖某个框架或某组 CSS 数值。文字的空格、标点和用词另见 [lailai's Text Format Guide](/docs/project/guides/text)；组件的具体用法另见 [laikit UI](/docs/project/ui)。

借鉴 Apple，是学习它对**内容、层级和平台习惯**的判断。不复制某一代系统的外观。Google Material 提供色彩角色的参考。Microsoft Fluent 与 IBM Carbon 分别提供设计变量和网格方法。各家的组件尺寸、圆角和动效参数不直接拼接成我的视觉风格。

## 原则

设计遵循 **统一、简约、现代**（Unity · Simplicity · Modernity）。三者不是装饰标签，而是取舍顺序。

1. **先保证内容和任务**：读者能找到信息，使用者能辨认状态并完成操作；视觉不得掩盖内容；
2. **再保证可用与可访问**：文字清楚，控件可操作；状态不只靠颜色或动画传达；
3. **保持整体统一**：同一含义沿用同一视觉语言。局部更好看却破坏整体一致的方案应放弃；
4. **最后打磨表现**：用比例、节奏、对齐和少量有意图的细节建立辨识度。

**简约不等于空白或简陋。** 删除无用装饰后，仍要有准确的层级、良好的比例和完整的细节。现代也不等于追逐流行效果；技术和形式应让作品更清楚、更适合当前载体。

## 视觉识别

- **保留自己的识别点。** 个人网站的彩色像素头像是标识；无需为了整体配色克制而把它改成单色。周围界面保持安静，让它成为明确的视觉中心。
- **让强调色承担明确职责。** 网站当前以蓝色表示链接、选中态和重点数据。其他产品可以换主色，但应保持「主色用于什么」的一致性，而非到处散落相近的颜色。
- **品牌色、功能色和内容色各司其职。** 成功、警告、错误使用稳定的状态语义；照片、地图和图表中的颜色按内容需要决定，不必强行染成品牌色。
- **同一作品先统一比例和笔触。** 头像、插画、图标可以使用不同手法。相邻元素的比例、边缘和视觉重量仍要协调。不要让单个素材压过标题或主要内容。

## 信息与版式

### 层级

- 先决定阅读顺序：主题、主要内容、辅助说明、元信息和操作。再用字号、字重、颜色、位置及间距表达，不靠层层套卡片或复杂装饰制造层级。
- 同一页面通常只保留一个最强的视觉起点。多个同级「主角」会互相争夺注意力；次要信息应容易找到，但不应抢先被看见。
- 相关内容靠近，异类内容分开。用留白、分隔线或背景层级中最轻的一种就够；除非它们各自承担不同职责，不要叠加多种分隔手段。
- 对齐是默认要求。标题、正文、按钮、图表刻度和卡片内容要共享可解释的基线或边线；必要的视觉居中可以微调，但不能以随意偏移掩盖结构问题。

### 密度与留白

- 留白要显示分组和呼吸感，也要与内容量相称。不能把「简约」理解为让少量内容悬在大片空白中；也不能为了填满屏幕而塞入无用元素。
- 同一类卡片使用一致的内边距、标题位置和信息顺序；并排卡片若属于同一组，检查实际高度、视觉重心和底边是否统一。
- 间距只设少量级别，清楚区分近、中、远。IBM Carbon 的网格可供参考，但不必让所有文字和图像落在单一像素倍数上。
- 长文以阅读宽度为先；目录、侧栏和工具栏是辅助。宽屏增加侧边空间，不应把段落拉成难以回读的长行。

### 响应式

- 按内容需要换布局，而不只是缩小桌面版。多列可变单列，侧栏可移到正文前后，辅助信息可折叠；标题和主要操作应保持可见且顺序稳定。
- 让文字自然换行，保留完整信息。省略号只用于用户能够在别处读到全文的辅助标签；重要标题、说明和错误信息不应被无声截断。
- 检查窄屏、横屏、文字放大和不同语言长度。页面不应出现横向滚动、重叠或被控件遮挡；代码、地图等确需二维操作的内容应在自身区域处理。

## 色彩与主题

- 界面的底色以柔和中性色为主，强调色少而准。大面积高饱和色会压过内容；照片、品牌标识和需要区分的数据不受这条限制。
- 将背景、表面、文字、边框、链接、选中和状态定义为语义色。浅色与深色主题分别调校，不能只反转明暗值。
- 不用颜色作为唯一信息通道。图表的升降还要有数字、箭头或文字；导航的当前位置还要有形状、线条或字重变化。
- 不把渐变作为页面背景或卡片的默认装饰。只有当渐变能表达连续数据、光照、材质或很轻的交互反馈，而且不损害可读性时才使用。首页导航卡片的局部悬停反馈属于后一种情况。
- 不把半透明面板铺满内容区。网站导航栏的磨砂效果用于区分浮在内容上方的导航层；正文、数据卡片和长文阅读面应保持稳定。任何透明材质都要在最亮、最暗及复杂背景上实测文字对比度，失效时改为不透明表面。
- 默认尊重系统的明暗偏好。若允许手动选择，用户应能恢复「跟随系统」。个人网站的主题与强调色设置是个性化功能，不必复制到每个产品。

## 字体与文字

- 正文优先用清楚、稳定、覆盖中英文的系统字体。个人网站以系统字体为先，Inter 作为补充；不要因为某款展示字体漂亮，就让长文阅读承担代价。
- 用有限的字号、字重和行距建立类型层级。小字不靠极细字重显得精致；大标题也不能只靠加粗而缺少与正文的比例关系。
- 中文、英文、数字混排时检查基线、标点、换行和字重。数字列表或指标卡可用等宽数字对齐；代码和标识符保留等宽字体的功能性，不扩展到普通正文。
- 长文的行距、段距和列宽要一起看。网站当前正文以 16px、约 1.65 行高为基线；这是现有实现，不是所有载体都必须照抄的常数。
- 标题尽量不留孤字成行，正文避免刻意挤成密块。优先改文案宽度或容器，而不是为了让一行恰好塞满而压缩字距。
- 界面文字说清操作和结果。按钮写动作，状态写含义，错误提示说明发生了什么和下一步；不要用装饰性文案替代信息。

## 形状与材质

- 圆角、边框和阴影要服务元素关系。相邻或嵌套元素可有不同圆角，但应呈现清楚的内外层级；同类组件不应各用一套数值。
- 优先通过表面明暗、边线和间距建立深度。阴影只用于确实浮在内容上方的元素或需要明确区分的交互层，不给每张卡片加同样的投影。
- 卡片用于承载**独立的信息单元或可点击对象**。连续文章、短标签和简单列表不必逐项装进卡片。首页的 Bento、博客指标和好友条目使用卡片，是因为它们各有清晰边界或目的。
- 透明、模糊和玻璃材质只用于确有层级关系的地方。借鉴 Apple 的材质原则，区分导航 / 控件层与内容层。

## 组件与交互

- 同一种任务尽量使用同一种控件：导航是导航，筛选是筛选，单项选择是单项选择。外观必须让人预期它的行为，不以相似的形状混淆链接、按钮和状态标签。
- 同类控件在默认、悬停、按下、焦点、选中、禁用、加载和错误状态下保持一套逻辑。状态变化要能看见，也要能通过文字或辅助技术理解。
- 优先复用既有组件与视觉变量，再设计新组件。新的卡片、按钮或提示即使单独更漂亮，也不应与相邻页面像来自两个产品。
- 悬停反馈给小元素即可：箭头轻移、图标或边线变化、背景微调。不要让整张卡片浮起或横移，导致布局显得躁动。
- 操作反馈要及时、可恢复。加载时保留结构；失败时给出原因和重试入口；空状态说明为什么为空、接下来能做什么。占位骨架只是等待状态，不能替代错误或空结果。

## 动效

- 动效用于解释**状态和空间关系**：展开、折叠、切换、进出场和操作回弹。运动应让用户看懂什么变了。
- 动画应短、轻、可打断。高频操作避免反复表演；大区域的运动尤其要克制。速度和缓动保持统一，不为每个组件设计一套曲线。
- 有物理隐喻的交互应符合动作本身。首页头像的拖拽回弹是直接操作的反馈；旅行地球的旋转帮助探索位置。它们可以比普通按钮更有个性，但不能阻塞主要内容。
- 尊重系统的减少动态效果设置。停用连续循环、夸张位移和自动运动，同时保留状态结果；不能让「减少动态」导致内容不可见。

## 图像与图标

- 图像先明确职责：说明内容、记录事实、承载品牌，或营造情绪。没有任务的装饰图应谨慎加入；有内容的图不应因统一配色而失真。
- 照片和作品图保留原有比例与关键主体。需要裁切时选择合适焦点，不拉伸，也不为了填满卡片牺牲重要信息。
- 界面图标保持相近的线宽、尺寸、细节层级和视觉重量。常见动作优先使用易识别的符号；含义不明或结果重要的动作应配文字标签。
- 标识、插画和界面图标可以不同风格，但不能混用多套竞争性的界面图标。彩色像素头像是品牌元素，不应成为把所有小图标都做成多彩像素风的理由。
- 图像中的文字、标注和符号应随实际展示尺寸检查。导出多个尺寸时逐一检查边缘、留白和清晰度，不能只看设计稿放大后的效果。

## 数据与可视化

- 先说明数据是什么、时间范围是什么、单位是什么，再选择图形。图表应帮助比较、看趋势或看构成；仅为填满页面而画图不如直接给数值。
- 指标卡先给核心数值，再给标签、趋势和解释。变化方向、变化幅度与好坏判断要分开：数值上升不一定代表情况变好。
- 同一图组统一坐标、刻度、颜色和交互方式。不同量纲不要伪装成可直接比较；需要截断坐标轴、累计或归一化时明确告知。
- 图表配清晰标签与可读的替代信息。颜色区分之外，还要有数值、图例或形状；动态数据注明更新时间，并提供加载、空数据和错误状态。
- 旅行地球首先让人理解访问过的地点，其次才展示空间效果。地图控件应清楚可操作，悬停信息不能成为获取地名的唯一途径；视觉层数和自动旋转不应拖慢浏览。

## 场景应用

- **[首页](/)**：以身份、主要入口和联系信息为先。Bento 让不同信息各有位置；彩色头像是唯一强品牌元素，导航卡片保持克制。
- **[文档](/docs/project/guides/design)与[博客](/blog)**：以阅读、查找和理解为先。标题、摘要、正文和目录组成阅读层级；侧栏与操作区不应争夺正文注意力。
- **[资源](/resources)与[友链](/friends)**：以筛选、辨认和前往目标为先。搜索与分类先于装饰；卡片和头像帮助扫读，同类条目的高度与信息顺序统一。
- **[旅行](/travel)**：以地点与空间关系为先。地球可以成为页面主角；统计、控件和时间线围绕探索任务安排。
- **[数据](/insights)**：以指标、趋势和状态为先。数值和时间范围先行；图表保持可比性，颜色表示状态时必须有其他线索。
- **[设置](/settings)**：以当前选择和修改结果为先。选中、预览、恢复默认和说明要清楚；个性化不能破坏可读性。

这些是现有作品的**设计逻辑**，不是要求所有页面都长成同一种卡片布局。统一的是字体、颜色语义、控件行为、间距关系和细节质量；页面结构可以随任务变化。

## 平面与输出

- 海报、封面、幻灯片、名片等从实际尺寸和观看距离出发。先确定信息顺序、标题面积与安全边距，再考虑装饰；屏幕预览不能代替实体尺寸检查。
- 印刷品核对成品尺寸、出血、裁切、安全区与色彩模式；屏幕图核对不同分辨率、压缩和缩略图效果。重要文字不要贴边，也不要只在大图中可读。
- 视觉标识优先保留可识别的轮廓。缩小、单色、浅底、深底后仍应成立；不能靠发光、复杂渐变或大段说明才能被辨认。
- 整套材料共用字体、色彩角色、对齐方式和图像处理规则。需要变化时，让变化对应主题或信息层级，而不是每一页重新发明风格。

## 无障碍与验收

- 以 WCAG 2.2 的 AA 级作为 Web 内容的基本检验目标。普通文字与背景的对比度至少为 4.5:1，大文字至少为 3:1；必要的控件边界和图形信息至少为 3:1。装饰、标识等例外按标准原文判断，不应误用为正文豁免。
- 可点击目标满足 WCAG 2.2 的最小目标尺寸或间距要求；移动端常用操作应进一步留出舒适的触碰范围。视觉上小的图标，可以有更大的实际点击区域。
- 用键盘走完主要任务，焦点必须可见；表单有标签，图像有合适替代文本，弹层可进入也可退出。地图、图表和拖拽交互应提供可理解的替代路径。
- 同时检查浅色、深色、窄屏、宽屏、文字放大和减少动态效果。至少看一次真实渲染结果，核对对齐、裁切、换行、状态和实际对比度；不要只凭设计稿或主观印象宣布完成。
- 当规则冲突时，先保住内容、可操作性和可访问性，再求视觉统一；确需破例，说明它服务的内容或行为，并检查是否引入新的不一致。
