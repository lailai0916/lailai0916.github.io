## 参与维护

组件、主题变量、类型声明与测试在 `lailai0916/ui` 仓库维护。问题反馈和功能建议可提交到 [Issues](https://github.com/lailai0916/ui/issues)，代码与文档改进通过 Pull Request 提交。

报告问题时附上组件库版本、React 版本和最小复现。修改公开属性、默认值或导出时，同步更新使用文档、示例、测试和迁移说明。新增接口前，先确认现有组件组合与主题变量能否满足需求。

提交前运行仓库检查。版本发布由有发布权限的维护者执行。

## 发布版本

在组件库仓库中运行：

```bash
npm ci
npm version patch --no-git-tag-version
npm run check
npm pack --dry-run
```

`npm version` 同时更新 `package.json` 与锁文件。兼容修复使用补丁版本；1.0 之前的不兼容修改提升次版本，并在 `CHANGELOG.md` 记录影响与迁移步骤。

`npm run check` 执行格式、Lint、类型、库构建、测试与示例构建。还应使用 `npm pack` 生成实际安装包，在使用方验证构建和界面。发布内容为 `dist/`、包元数据、README 与许可证，不应夹带项目私有配置。

将发布改动提交并推送到 `main` 后，等待工作流的 `validate` 与 `publish` 均成功，再检查：

```bash
npm view @lailai0916/ui version
npm view @lailai0916/ui repository.url
```

确认版本与源码对应后，创建匹配的版本标签与 GitHub Release。标签用于追踪发布，当前自动发布由 `main` 提交触发。

## 自动发布规则

| 操作                                         | 结果                         |
| -------------------------------------------- | ---------------------------- |
| 推送 `main`，版本尚未发布，检查通过          | 自动发布到 npm               |
| 推送 `main`，版本已在 npm 存在               | 跳过发布                     |
| 修改代码但不提升版本                         | 不会覆盖 npm 中的旧代码      |
| 提交 PR 或推送标签                           | 只验证，不发布               |
| 在 `main` 手动运行 `CI`                      | 验证后按同一规则决定是否发布 |
| 检查失败、注册表异常或待发布版本低于最新版本 | 停止发布并报告失败           |

当前流程接受稳定的 `X.Y.Z` 版本。预发布版本需要另行设计 dist-tag 规则。已发布版本不能覆盖，修复后发布新版本。

## 应用升级

在应用中安装目标版本：

```bash
npm install --save-exact @lailai0916/ui@0.2.0
```

把示例中的 `0.2.0` 替换为要升级的已发布版本。使用 npm workspaces 时，在依赖组件库的工作区执行安装，或通过 `--workspace` 指定工作区。

提交应用的依赖清单和锁文件，并运行应用自身的类型检查、测试和生产构建。检查浅色、深色、系统主题、窄屏布局、表单和键盘操作。从旧包迁移时，按照 [迁移指南](/docs/project/ui/migration) 处理接口差异。

## 发布连接

npm 的 Trusted Publisher 应与实际仓库和工作流保持一致：

| 字段                 | 值             |
| -------------------- | -------------- |
| Provider             | GitHub Actions |
| Organization or User | `lailai0916`   |
| Repository           | `ui`           |
| Workflow Filename    | `ci.yml`       |
| Environment Name     | 留空           |
| Allow npm Publish    | 启用           |

CI 使用 GitHub 托管运行器、Node.js 24 和 OIDC 临时发布凭据，不需要保存 `NPM_TOKEN`。正常发布无需打开 npm 网站；仓库重命名、工作流文件改名或发布权限变化时，仍需更新该连接，npm 可能要求账号安全验证。

## 故障处理

先查看失败的工作流步骤。验证失败时修复源码；身份验证失败时核对仓库、工作流和 npm 发布连接；注册表异常时确认版本状态后再重跑。已存在的版本会被跳过，不能靠重跑覆盖。

应用升级后出现回归时，先将依赖及锁文件恢复到上一个已验证版本，重新构建并部署。向组件库提交最小复现，修复版本发布后再验证升级结果。
